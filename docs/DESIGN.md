# DESIGN

## データ

最初はメモリ上のみで永続化なし。
永続化するならSQLiteを使う。

### ルーム
- ルームID: uuid生成
- ルーム名: ユーザーが決定
- Players: 参加プレイヤー
- プレイ時間
- 開始時間

### プレイヤー
- プレイヤー名
- 進行状態


## API

### 認証
ルームごとの合言葉と表示名で参加する。Discord認証は使わない。
作成後・参加後はルーム専用のHttpOnly Cookieで本人を識別する。
ルーム作成者は管理者となり、プレイヤーには自動参加しない。管理者は参加せずにカード再生成・開始・終了・進捗閲覧を行える。
定員はプレイヤー4名で、管理のみの作成者は含めない。作成者も明示的に参加すれば1枠を使用し、開始前は管理権限を保ったまま参加を取り消せる。
プレイヤーが1名以上いると開始でき、試合開始後の新規参加は禁止する。

### 取得
フロントエンド側で取得する際にアクセスするAPI。
- `GetRoomStatus`: ルームの情報を取得
- `GetPlayerStatus`: ルーム内のプレイヤーの情報を取得

### 更新

- `UpdatePlayerProgress`
- `UpdateBowser`: クッパ撃破を記録する

### プロトタイプ

実装済みのHTTP APIと操作手順は `DEVELOPMENT.md` と `README.md` に記載。
基本の勝利条件は「同一プレイヤーによる1ライン完成＋クッパ撃破」。
RaceとLockoutを選択でき、進捗共有はWebSocketで変更直後と1秒ごとに行う。
切断時は1秒間隔のHTTP取得に切り替え、WebSocketへ自動再接続する。
