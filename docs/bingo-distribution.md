# Bingo マス分布設計

## 前提と現状

- 全員同一カードのRace / Lockout。基本ルールAは「1ライン完成＋クッパ撃破」、派生ルールBは「1ライン完成」。
- GAME_NOTE.mdの調査を踏まえ、既存51件のうち条件未確定の11件を保留し、40件を抽選対象とする。保留は不可能という判定ではない。
- 既存の `timeMin`、区間時間、固定クッパ時間は実測前の暫定値。時間条件は計算上の採用条件であり、指定時間内の完走や全ラインの均等性を保証しない。
- 現在、経由区間が登録された1件も保留対象であり、有効候補には経路設定がない。実データの道中補正・クッパ補正を有効にするには、下記の計測・設定が必要。未測定値を推測で登録しない。

## お題データ（BingoGoal）

- `name`：達成条件。単一コースは `world` / `level` に場所を分離し、複数対象は内容中に列挙する。
- `world` / `level`：表示・配置用の場所。指定なしは空文字。経由区間とは独立。
- `timeMin`：新規開始から単独達成まで。到達・解放・準備・作業を含み、失敗のやり直しは含めない。1〜1440分の整数。
- `exec` / `risk`：1〜3。`cost = timeMin × (1 + 0.3 × (risk - 1))`。execは表示用。
- `tags`：area/type各1〜2件。配置の偏りを抑えるソフト制約。
- `routeAreas`：共有可能な解放作業の区間ID。未登録・重複を拒否し、区間時間合計はtimeMin以下。
- `disabledReason`：省略・空文字なら抽選対象。理由を入力すると保留し、抽選・時間の上下界から除外。データ自体は保存する。保存時には抽選対象25件以上を要求する。
- `conflictGroups`：同じグループを持つお題を同一ラインに置かない。空・重複・前後空白・カンマを拒否。包含・似た作業を保守的に分離する仕組みであり、経路共有や実行順序を表すものではない。

## 経路データと評価

`routeAreaTimes`は区間単体の時間。地域名から経路を推測せず、同じIDに同じ解放作業を対応させる。解放後の往復・再入場・装備再調達・両出口の攻略費用を共有区間に含めない。

`backend/bingo/route_segments.json`にバニラの分岐、ドーナツ通常／星方面、森の城／砦、チョコレー本線／ひみつ、谷の正面／裏口、星の各隠し出口を登録する。提示した区間は粒度の出発点であり、途中のお題には必要部分だけの別IDを定義する。星から地上地域全体へ移動できるとは扱わない。

`retiredAreas`に指定された旧地域ID（バニラドーム、バニラだいち、ドーナツ、森、チョコレー、谷、スターロード）は読み込み互換を保つが、重複控除に使わない。管理画面では値を参考として残し、抽選対象のお題は区間の再指定が必要。保留中は旧参照を保持できる。新しい未使用区間は時間未設定でも保存できる。

バニラ1の共通区間は分岐前までで、通常／隠し出口の攻略・再入場は別計上する。既存の1分は校正済みではない。2出口を1回で済ませるモデルではない。

ラインのお題費用は `Σ cost − Σ((同一区間の使用回数 − 1) × 区間時間)`。リスク加算は維持する。作業の同時達成は時間控除しない。

### クッパ経路（bowserRoutes）

カタログに任意の `bowserRoutes: [{ name, timeMin, routeAreas }]` を登録できる。

- `timeMin`は開始からクッパ撃破までの単独経路時間（1〜1440分）。
- `routeAreas`はお題と共有できる解放区間。重複・未登録・旧地域IDを禁止する。
- 区間時間合計はtimeMin未満とし、移動・再入場・戦闘の時間を残す。
- 各ラインと各クッパ経路について、`ラインのお題費用 + 経路timeMin − 共有解放区間の和` を評価する。同じ区間はライン内に何件あっても、クッパ分からは1回だけ引く。
- 基本ルールAの見積もりは全12ライン・全登録経路の最小値。単独最速のクッパ経路が、そのラインにも最適とは限らない。
- 未登録時だけ従来の `minLine + baseRoute` を暫定値として使用する（既定baseRouteは15分）。経路を登録した場合はbaseRouteを重ねない。ルールBはどちらも加算しない。

これは解放区間の集合による近似。単独経路の合併が最適である保証、装備・移動順の自動検証、不可逆な進行の計画は含まない。実測時に両立する経路として確認する必要がある。現在のカタログにクッパ経路の実測値は登録していない。

## 生成ロジック

- 保留を除いた候補から25件を抽選する。seedによる再現性は同じカタログ・設定・アルゴリズムで保証する。今回の変更前と同じカードになる保証はない。
- 中央→斜め上→その他の固定順で配置する。
- 全12ラインで同じ空でないworldと、同じconflictGroupsを重複させない。world制約は地域の多様性を保つ既存方針として維持し、依存関係の代用にはしない。
- `score = tagPenalty + 補正後の全12ライン見込み時間の平均絶対偏差`。未配置マスは抽選候補の平均単独コストで仮補充する。平均の比較基準も補正後とし、補正前の5倍平均を使わない。
- tagPenaltyは配置マスの所属ライン内の一致数（area=2、type=1）。同点はseed由来のRNGで選ぶ。
- 完成後、Aはクッパ経路込み、Bはお題のみの最短ライン見積もりが `[minTarget, maxTime]` に入るか判定する。配置スコアはお題時間で評価し、クッパ経路は最終採用時に評価する。
- 配置不能・時間条件外なら再抽選し、256回で見つからなければエラー。狭い範囲では成立するカードを見逃す場合がある。
- 時間下界は、経由時間を除いたコストの小さい5件の和と5番目に安い単独コストの大きい方。上界は高い5件の和。クッパ経路登録時は下界に0、上界に最短の単独クッパ経路時間を加え、共有可能な経路を早期に誤って拒否しない。未登録時は両方にbaseRouteを加える。

## 保存・ルーム・管理画面

お題、区間時間、クッパ経路を同一スナップショットで生成し、カードにコピーする。カタログの保存・再読み込み・編集用コピーから既存ルームは影響を受けない。開始後の再生成は禁止する。

管理画面で保留理由、配置禁止グループ、クッパ経路を編集できる。旧データの省略フィールドは従来互換。保存前に有効件数・参照・時間を検証する。画面の時間表示は暫定見積もりとする。

## 検証と残作業

自動テスト：全12ラインのworld／グループ制約、保留除外、有効件数、seed再現性、200シードの実データ生成、共有区間控除、クッパ経路選択・上下界・A/B、補正後スコア、入力検証、コピー独立性、管理APIの保存・再読込、フロントの編集往復。

実測・競技上の残作業：

- 日本版SFC、新規開始、バグ技・退出・ミス・リセットの扱いを正式に決める。
- 保留11件の対象と達成条件を確定し、映像等で検証してから再有効化する。残る40件も実機での成立性監査済みという意味ではない。
- 到達・解放、再訪、装備調達、作業、クッパまでの残りを分けて計測し、timeMin・routeAreaTimes・routeAreas・bowserRoutesを校正する。
- 同時達成、実行順序、失敗による再調達は本モデル外。必要に応じて条件の明文化や保留・配置グループで対応し、単なる地域一致から費用を差し引かない。
- β=0.3、タグ重み、候補数・時間分布の妥当性をプレイ結果で見直す。
